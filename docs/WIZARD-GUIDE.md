# Configuration Wizard Guide

The `mydock` wizard helps you create configuration files interactively without needing to remember all the parameters.

## Two Wizard Modes

### 1. Full Wizard (`wizard`)
Comprehensive setup with all options

### 2. Quick Wizard (`quick`)  
Minimal questions for fast setup

## Using the Wizard

### Standalone Mode

```bash
./mydock wizard
```

This launches the full configuration wizard that guides you through:
1. Selecting a Docker image
2. Setting container details (name, hostname)
3. Configuring directory mappings
4. Setting up user mirroring
5. Port mappings
6. Network configuration
7. Saving and optionally running the configuration

### In Interactive Mode

```bash
./mydock interactive
mydock> wizard
```

Or for quick setup:
```bash
mydock> quick
```

## Full Wizard Walkthrough

### Step 1: Docker Image Selection

The wizard shows available images on your system:
```
Available images on your system:
REPOSITORY                                          TAG      ID            SIZE
gunnar.lab.tail-f.com:5000/tailx-sdk-baseimage     v1       abc123def     2.5GB
kruskakli/my-debian                                 v5       def456ghi     1.8GB
debian                                              latest   ghi789jkl     124MB

Enter image repository (or 'custom' for URL):
```

**Options:**
- Type an existing repository name from the list
- Type `custom` to enter a full URL (e.g., `myregistry.com:5000/myimage`)
- Press Tab for autocomplete (if your shell supports it)

**Example:**
```
Enter image repository (or 'custom' for URL): debian
Enter image tag [latest]: bookworm
```

### Step 2: Container Details

Set the container name and hostname:
```
Enter container name: my-dev-container
Enter hostname [my-dev-container]: devbox
```

- **Name**: Unique identifier for the container
- **Hostname**: How the container identifies itself (defaults to name)

### Step 3: Directory Mapping

Specify the main shared directory:
```
Enter shared directory path (required): /home/tobbe/work/git/myproject
```

The wizard will:
- Expand `~` to your home directory
- Check if the directory exists
- Offer to create it if missing

### Step 4: User Mirroring

One of the most powerful features!

```
User mirroring creates a user in the container matching your host user.
This ensures file ownership is correct when editing files from the container.

Enable user mirroring? [Y/n]: y
```

If enabled, you can add additional directories to mount:
```
Additional directories to mount (with matching paths):
Press Enter with empty input when done.
Use ':ro' suffix for read-only mounts (e.g., /home/user/.ssh:ro)

Directory path (or Enter to finish): /home/tobbe/projects/another-project
✓ Added: /home/tobbe/projects/another-project

Directory path (or Enter to finish): ~/.gitconfig:ro
✓ Added: /home/tobbe/.gitconfig:ro

Directory path (or Enter to finish): 
```

**Smart Suggestions:**
If you don't add any directories, the wizard suggests common ones:
- `~/.gitconfig:ro` - Your Git configuration
- `~/.ssh:ro` - SSH keys for Git/remote access

### Step 5: Port Mapping

Map ports from your host to the container:
```
Map ports from host to container (format: HOST:CONTAINER).
Press Enter with empty input when done.

Port mapping (e.g., 8080:80) or Enter to finish: 9080:8080
✓ Added port mapping: 9080:8080

Port mapping (e.g., 8080:80) or Enter to finish: 3000:3000
✓ Added port mapping: 3000:3000

Port mapping (e.g., 8080:80) or Enter to finish: 
```

**Format**: `HOST_PORT:CONTAINER_PORT`
- `9080:8080` - Access container's port 8080 via host's port 9080
- `3000:3000` - Direct mapping

### Step 6: Docker Networking

Configure advanced networking:
```
Configure Docker network? [y/N]: y

Available networks:
NETWORK ID     NAME      DRIVER    SCOPE
abc123def      bridge    bridge    local
def456ghi      mynet     bridge    local

Enter network name (or create new): dev-network
Network doesn't exist. Auto-create it? [Y/n]: y
Network driver [bridge]: bridge
```

The wizard can:
- Connect to existing networks
- Create new networks automatically
- Configure network drivers

### Step 7: Save Configuration

```
Configuration filename [my-dev-container.conf]: 
```

The wizard:
- Suggests a filename based on container name
- Automatically adds `.conf` extension if missing
- Warns if file exists
- Shows the generated configuration

**Generated Configuration Example:**
```bash
# mydock configuration file
# Generated by wizard on 2025-10-10 14:30:00

# Container image
REPOSITORY=debian
TAG=bookworm

# Container details
NAME=my-dev-container
HOSTNAME=devbox

# Directory mapping
SHARED_DIR=/home/tobbe/work/git/myproject

# Port mappings
PORTS=9080:8080
EXTRA_RUN_FLAGS="-p 3000:3000"

# ========================================
# User Mirroring Configuration
# ========================================
# Enable automatic user mirroring
MIRROR_USER=yes

# User settings (auto-detected if not specified)
MIRROR_USER_NAME=tobbe
MIRROR_USER_UID=1000
MIRROR_USER_GID=1000

# Directories to mount with matching paths
MIRROR_DIRS=(
  "/home/tobbe/projects/another-project"
  "/home/tobbe/.gitconfig:ro"
  "/home/tobbe/.ssh:ro"
)

# ========================================
# Network Configuration
# ========================================
NETWORK_NAME=dev-network
NETWORK_DRIVER=bridge
NETWORK_CREATE_IF_MISSING=yes
```

### Optional: Run Immediately

```
Would you like to run this configuration now? [y/N]: y
Dry-run first to see the command? [Y/n]: y

ℹ Running dry-run...
sudo docker run -dt --privileged -v /home/tobbe/work/git/myproject:...
```

This lets you:
1. Preview the command (dry-run)
2. Create and start the container immediately
3. Or save for later use

## Quick Wizard

For fast setup with sensible defaults:

```bash
./mydock quick
```

**Prompts:**
1. Image repository (shows recent images)
2. Container name
3. Directory to map

**Auto-configured:**
- User mirroring: ON
- Common directories: `~/.gitconfig:ro`, `~/.ssh:ro`
- Latest tag
- Hostname = container name

**Example Session:**
```
mydock Quick Setup

Recent images:
REPOSITORY                TAG
debian                    latest
kruskakli/my-debian      v5

Image repository: debian
Container name: quick-dev
Directory to map: ~/work/myproject

✓ Created: quick-dev.conf

# Quick setup configuration
REPOSITORY=debian
TAG=latest
NAME=quick-dev
HOSTNAME=quick-dev
SHARED_DIR=/home/tobbe/work/myproject

# User mirroring enabled
MIRROR_USER=yes
MIRROR_DIRS=(
  "/home/tobbe/work/myproject"
  "/home/tobbe/.gitconfig:ro"
  "/home/tobbe/.ssh:ro"
)

Run now? [y/N]:
```

## Tips & Tricks

### 1. Tab Completion
If your terminal supports it, use Tab to autocomplete paths and names.

### 2. Tilde Expansion
The wizard automatically expands `~` to your home directory:
- `~/projects` → `/home/tobbe/projects`

### 3. Read-Only Mounts
Use `:ro` suffix for directories you don't want to modify:
- `~/.ssh:ro` - Prevents accidental changes to SSH keys
- `~/.gitconfig:ro` - Protects Git configuration

### 4. Edit After Creation
You can always edit the generated `.conf` file manually:
```bash
nano my-dev-container.conf
```

### 5. Reuse Configurations
Create a base configuration and duplicate it:
```bash
cp base-dev.conf project1.conf
# Edit project1.conf to change name and directories
```

### 6. Version Control
Add your `.conf` files to Git for team sharing:
```bash
git add *.conf
git commit -m "Add container configurations"
```

## Common Scenarios

### Scenario 1: Simple Development Container

```
./mydock quick
Image: debian
Name: dev
Directory: ~/projects/myapp
```

Result: Container with user mirroring and common tools mounted.

### Scenario 2: Multi-Port Web Application

```
./mydock wizard
Image: node
Name: webapp
Ports: 3000:3000, 9229:9229 (debugging)
User mirroring: Yes
Directories: ~/projects/webapp, ~/.npmrc:ro

Result: Node.js container with app and debugging ports.

```
./mydock wizard

Name: test-isolated

```

Result: Container in isolated network for testing.

### Scenario 4: Database Development

Name: dev-db
Ports: 5432:5432
Directory: ~/data/postgres
Network: db_network
```

Result: PostgreSQL with persistent data directory.

## Troubleshooting

### Issue: "Directory does not exist"
**Solution:** Let the wizard create it, or create manually first:
```bash
mkdir -p ~/projects/myapp
```

### Issue: "Network already exists"
**Solution:** The wizard will detect and use the existing network.

### Issue: "File exists. Overwrite?"
**Solution:** 
- Choose `y` to overwrite
- Choose `n` and specify different filename

### Issue: Generated config doesn't work
**Solution:** Check with dry-run:
```bash
./mydock run --config myconfig.conf --dry-run
```

## Next Steps

After creating a configuration:

1. **Test it with dry-run:**
   ```bash
   ./mydock run --config myconfig.conf --dry-run
   ```

2. **Create the container:**
   ```bash
   ./mydock run --config myconfig.conf
   ```

3. **Enter the container:**
   ```bash
   ./mydock user --name container-name --user your-username
   ```

4. **Manage it:**
   ```bash
   ./mydock stop --name container-name
   ./mydock start --name container-name
   ./mydock rm --name container-name
   ```
